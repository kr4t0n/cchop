# cchop contributor context

cchop is a global npm CLI implementing the source document's personal Claude Code subscription relay: capture a remote request identity once, then rewrite incoming client requests and manage the remote subscription OAuth credentials. The user explicitly requested this architecture, replacing the earlier passthrough proxy. The application and bundled React dashboard run in one foreground process. A Dockerfile packages both cchop and Claude Code; infrastructure orchestration remains outside this repository.

## Architecture

- `src/cli.ts`: initialization, separate one-time capture, foreground relay/dashboard startup, diagnostics, and private client settings generation.
- `src/config.ts`: strict configuration, external state paths, and environment-backed relay/admin keys. Relative state paths resolve against the configuration directory.
- `src/capture.ts`: loopback-only HTTP capture of the first valid remote Claude messages request. Forward the original request and stream its response, then exit; never refresh credentials during capture.
- `src/fingerprint.ts`: validate and atomically persist format-versioned reusable headers, only the remote `device_id` and `account_uuid` in an `identity` object, capture time, and Node version. No prompts, provider credentials, session IDs, other metadata user-ID fields, or per-request headers belong in a fingerprint.
- `src/identity.ts`: shared device/account schema, parsing of JSON-encoded `metadata.user_id`, session header/body consistency checks, and classification of all `x-claude-code-*` headers as request-scoped.
- `src/rewriter.ts`: strip client device/runtime and credential headers, apply reusable captured headers, replace only device/account fields inside an existing metadata user ID, and inject the remote OAuth token last. Preserve current session, agent, parent-agent, prompt IDs, and request hints.
- `src/credentials.ts`: reread remote Claude credentials for every request; use stored OAuth client/scopes with the configured client ID as fallback; serialize early refresh with one in-process promise; validate and atomically persist access/refresh tokens, expiries, and granted scopes before releasing the new access token. Retain the old refresh token when rotation is omitted.
- `src/server.ts`: independent relay/admin listeners, bounded proxying, streaming, cancellation, lifecycle, and sanitized diagnostics.
- `src/types.ts`, `src/metrics.ts`: bounded request metadata and dashboard status. `GET /api/status` requires `X-Cchop-Admin-Key`.
- `web/`: React, TypeScript, Vite, and Tailwind operations dashboard, built into the npm package.
- `Dockerfile`, `.dockerignore`: multi-stage build from a pinned current Node Debian slim image, compiled cchop with lockfile-installed production dependencies, and a pinned official Claude Code npm installation. Tini supervises the foreground command; runtime uses UID/GID 1000. The build context is allowlisted and excludes secrets and local artifacts.
- `test/`, `scripts/`: local protocol/credential/capture/CLI checks and foreground-supervised package/browser/Docker smoke checks. Docker checks use a temporary named volume and containers with networking disabled. Never read actual user credentials or use real provider tokens in automated tests.
- `.github/workflows/publish.yml`: validate a tagged stable GitHub release, publish the tested tarball to npm using OIDC and provenance, and verify registry integrity. Manual workflow dispatch performs validation and a dry run only.

## Required mechanism

- The source document is https://bytedance.larkoffice.com/wiki/OkVnw34DTilaLMkaUI5ceE7enbf. Honor its capture → strip local identity → apply remote identity → replace OAuth → stream response flow. Do not substitute client-authentication passthrough again.
- The local client's `ANTHROPIC_AUTH_TOKEN` is the relay key. Authenticate it with constant-time hash comparison, strip it, and set upstream Authorization to the remote access token. The generated client settings contain only the relay URL and shared relay key.
- Capture omits authorization, API keys, cookies, gateway keys, hop-by-hop headers, and forwarded addresses. Captured headers intentionally replace current local beta/version/runtime headers; do not merge local capabilities into a frozen capture.
- Capture excludes all `x-claude-code-*` headers. Relay forwarding preserves current session, agent, parent-agent, and prompt IDs along with request hints (request class, agent type, compaction, tool durations). Absent correlation headers stay absent; never freeze or remap them.
- Parse an existing `metadata.user_id` as a JSON-encoded object and replace only `device_id` and `account_uuid` with captured values, preserving `session_id` and unknown fields. This field-level substitution supersedes the source document's whole-user-ID replacement at the user's request. Missing metadata or a missing user ID stays absent. Reject malformed/compressed requests and session header/body conflicts before OAuth refresh or inference. Do not forward stale content length.
- Refresh within five minutes of access-token expiry. Use the credential's `clientId` when present, otherwise the configured fallback, and request only stored nonempty scopes. Atomically persist the new access token and expiry, rotated refresh token when supplied, granted scopes, and refresh-token expiry; retain previous values for omitted response fields. Preserve unrelated credential metadata and fail with 503 if refresh or persistence fails. Never log response bodies or token values. Do not automatically retry inference or redirect authenticated traffic.
- One person, one subscription, one relay process. Stop remote Claude Code before starting the relay so credential writes have a single owner. Capture runs only while relay service is stopped; upgrades require explicit recapture.
- The only authentication mode is `subscription`. Old `passthrough`/`api-key` configuration is rejected with migration instructions. Authentication behavior must never change silently.
- Admin defaults to a separate loopback listener and independent secret. Prompt content, metadata.user_id, and credentials must never appear in logs or retained history. Process supervision and network setup belong to the operator.

## Conventions

- TypeScript, ESM, explicit `.js` extensions for server imports; exact dependency versions and lockfile.
- Run ESLint, type checks, build, and meaningful tests after changing code. Run package/browser checks when their paths or contracts change.
- Run `docker build --pull -t cchop:local .` and `npm run test:docker` after changing container packaging; CI runs both. Keep Node's version/digest and Claude Code's version explicit. Container publication is not part of the npm release workflow.
- Update README and this architecture description with behavior and setup changes.
- Package only compiled application assets and documentation. Keep `.env`, fingerprint.json, Claude credentials, local client settings, npm authentication, and local configuration out of git and package tarballs.
- Publishing the npm package requires explicit user authorization. The release workflow treats publication of a stable GitHub release as authorization to publish its matching npm version; pushes and manual validation runs do not publish.
- Release versions are duplicated in the root/web package manifests, lockfile, `src/config.ts`, and the installed-version assertion in `scripts/package-smoke.ts`; keep them aligned. Commit version changes, tag that commit, and publish its GitHub release to start automated checks and npm publication. Publish the tarball validated by the package smoke check and verify registry integrity before announcing availability.
- npm trusted publishing must authorize `kr4t0n/cchop`, workflow filename `publish.yml`, no environment restriction, and direct `npm publish`. Use GitHub-hosted runners and a compatible npm CLI; no long-lived npm token is required. Keep the publish workflow self-contained so its OIDC workflow identity matches the configured filename.

## Gotchas and limits

- Docker persists the entire `/home/node` volume, including Claude's `.claude.json` and `.claude/` and cchop's `.config/cchop/`. Executables stay outside that volume, so rebuilds replace binaries without replacing login state. Bind mounts must be writable by UID/GID 1000. Do not mount the operator's home or run multiple credential writers.
- Docker overrides relay/admin binds to `0.0.0.0`; restrict published host ports explicitly, especially administration. Capture remains loopback-only and Claude must run in the same container. Use a setup shell as the container's main process during capture so its completion does not kill the interactive Claude client. Exit Claude and the setup shell before starting the relay. Automatic/manual Claude updates are disabled; rebuild and explicitly recapture after upgrades. Allow more than `shutdownGraceMs` when configuring Docker's stop timeout.
- Default Claude credential storage follows the document's Linux JSON format. Keychain extraction is not implemented. A custom CLAUDE_CONFIG_DIR must be reflected in cchop's explicit credential path.
- Capture exits after its first selected exchange, including provider errors; saving a fingerprint does not establish successful provider authentication. A non-successful captured exchange is reported by the CLI.
- Align the relay Node major version with capture. The stored version describes cchop's capture process, not a verified match to the Claude executable's embedded TLS stack. No guarantee of TLS equivalence or account-enforcement outcomes is made.
- OAuth refresh has one in-process owner. Concurrent independent processes writing the same file are unsupported. A stale backup refresh token may be revoked; recover with a new remote login rather than assuming rollback works.
- Refresh responses need not rotate the refresh token. Missing `refresh_token` retains the current token, while null, empty, or otherwise malformed replacements fail validation. `scope` updates stored `scopes` when supplied (an empty string clears them); `refresh_token_expires_in` updates `refreshTokenExpiresAt` in milliseconds (zero means immediate expiry). Omitted scope/refresh-expiry fields preserve existing values. The recorded refresh-token expiry is metadata, not a local preemptive rejection rule; the token endpoint determines validity. Legacy files may omit optional `clientId`, `scopes`, and `refreshTokenExpiresAt`; malformed present fields fail before refresh. No default scopes are invented and unrelated metadata remains intact.
- Configuration JSON, gateway credential file, fingerprint, and Claude credential paths must be distinct. Fingerprints are loaded at startup; OAuth credentials are reread per request.
- Fingerprints use `schemaVersion: 2` with a strict `identity` object containing only `device_id` and `account_uuid`. Unversioned, version-1, and unsupported formats fail startup with explicit `cchop capture --replace` instructions, also surfaced by doctor; never silently upgrade them. Capture requires a nonempty device ID and a string account UUID (which Claude Code may leave empty without a cached account profile). Capture and relay validate matching session IDs when both header and body provide them, but neither require nor synthesize missing session IDs. Preserving client session IDs needs no mapping state and retains continuity across relay restarts. Persisted per-request headers or extra identity fields fail validation.
- Capture never retains prompts. Runtime history is bounded and per process; restarting clears it. Latency covers only retained requests.
- A configured base URL does not control every Claude Code network endpoint; login and auxiliary features may use other routes.
- Mock protocol and rotation tests do not prove live subscription compatibility. Do not claim live validation unless it was actually performed with the operator's authorization.
- Graceful shutdown has a deadline; remaining streams and OAuth network work are cancelled at that deadline. Once a successful OAuth response has been validated, finish its atomic credential commit even during shutdown so a possible rotation and its metadata are not lost.
- A locally installed tarball does not verify registry publication. Confirm the published version and artifact integrity before announcing a release.
- Manual publish-workflow runs validate packaging without exercising OIDC publication. Prereleases are skipped; stable releases require a new `v<version>` tag matching the manifests and CLI. A rerun after successful npm publication cannot overwrite that version.
- npm 11 rejects an already-published version even in a publish dry run. The preview step uses `--dry-run --force` so the current version remains testable; the real publication step must never use `--force`.
